# 2026/10/04｜水下光柱调试、Blender 建模操作

今天接着排查水下光柱。昨天已经能看到海床上的动态亮斑，但水中的亮暗带始终不明显，地面焦散和体积光也曾被混在一起判断。这次没有继续一味加灯、调雾，而是回到当前材质的实际输出，把水深判断、水下后处理和光照图案拆开做对照。

## 光柱终于留下来了

上午的测试发现，两段计算叠在一起压掉了光柱。太阳 Light Function 中的水深判断，会削弱用于体积雾的动态光照图案；水下后处理又对已经渲染出来的画面做吸收染色，把雾里的明暗变化进一步压淡。之前怀疑过材质与 Light Function Atlas 的兼容性，但这次没有把那个猜测直接当成结论，最后还是通过当前关卡的对照找到了更具体的问题。

先在太阳材质副本里保留动态波形，绕过后面的水深计算，再临时把水下染色材质的权重设为零。水中开始出现很淡的光柱，提高太阳的体积散射强度后，中央和右侧的亮暗变化更明显了。这次看的确实是悬在海床上方的光，而不只是落到地面的大亮斑。

接下来恢复蓝绿色水感。AI 提供了后处理的测试修正：对深度极大的背景像素保留原本的场景颜色，避免用同一套吸收计算覆盖已经由体积雾生成的光柱；海床和岩石继续接受水下染色。粘贴代码时一度重复定义了变量，材质没有编译成功，清空后重新粘贴才解决。恢复后处理权重后，水下颜色和光柱终于可以同时保留。

这仍然是针对当前场景的近似修正，并不是已经完成了准确的水下光传输。尤其是体积雾中的光照投影坐标，不能直接当成光束每个位置的真实水深。想让一条光束从水面到海底逐渐衰减，还需要进一步处理体积介质，而不是只在现有 Light Function 里改几个深度参数。

## 让焦散与太阳有联系

光柱能看见后，开始整理它与细碎焦散的关系。希望焦散主要出现在太阳能够照到的地方，而不是继续被固定在一个独立的圆形区域里。

这里也补了一点原理上的区分：水中的光柱来自散射进入视线的光，海床上的焦散则是光经过水面折射、聚集后形成的亮纹。光柱是否明显还与观察角度和介质有关，因此不能直接拿屏幕上看见的光柱轮廓去裁焦散。

实际操作先统一焦散灯与太阳的照射方向，再把太阳材质里的动态遮罩复制到焦散材质中，替换原来的固定圆形遮罩，让细碎纹路乘上同一套大块亮区。遮挡交给灯光阴影处理。这一步建立了两种效果之间的联系，但聚光灯与方向光的投影并不天然重合，光柱与焦散的精确对齐仍然没有完成。

下午又发现，光柱不只出现在海床上方，也延伸到了模型外面，甚至水面以上。最初尝试平移图案，结果并没有解决。后来重新看全景，问题更清楚了：海床模型有边界，用来显示光柱的全局雾却没有对应的水体边界。移动重复图案只能换个落点，不能把水下介质裁到水面以下。这个范围问题先留下，不再继续盲调偏移。

傍晚决定把项目暂时停在这一版。水下染色、地面焦散和太阳体积光已经可以一起观察，画面也有了空间层次，但亮斑仍偏大，岩石与背景的关系、介质范围和性能都还需要处理。AI 的帮助主要在诊断脚本、HLSL 修正和操作讲解；材质接入、参数修改、画面对照和效果取舍则是在实际调试中逐步确认的。

## Blender 与渲染基础

晚上继续补 Blender 的建模操作。倒角问题的关键不是“有没有缩放过模型”，而是缩放之后有没有应用 Scale。对象被拉长、压扁后，非均匀缩放仍留在变换里，会影响后续倒角的宽度和形状。这次把“调整外形”和“应用缩放”分开理解，不再把它们当成同一个操作。

还问了 Boolean 怎样删除交叠部分。这里需要的是 Difference：选中要保留的主体，用另一个物体作为切割体，从主体中减掉两者重叠的部分。操作步骤和常见问题已经讲解，但当天的记录没有确认最终切割结果，不能算作完成了一个新的模型。

随后补看了渲染管线的整体概念：模型和相机数据怎样经过顶点处理、光栅化、像素着色、深度与混合，再到后处理和最终画面。把它与这几天的操作放在一起，水面材质、Light Function、体积雾和水下后处理不再只是几个零散名字，而是各自影响画面不同环节的部分。这次主要是概念梳理，还没有独立实现一套新的渲染管线。

另外简单了解了 Godot 的节点与场景组织方式，也讨论了一门 Agent 与 MCP 课程。后者目前只是了解课程内容和学习价值，没有确认开始学习或完成项目，不记成新的实践成果。

水下项目先保留一个可以回看的阶段版本。暂时停下不代表所有问题都解决了，而是已经能明确区分：哪些效果确实出现了，哪些只是近似，下一次回来还需要处理什么。
